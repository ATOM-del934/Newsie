# 🐋 全球一周速览 · Electron 托盘版

常驻系统托盘的桌宠。**关掉气泡它也还在**，每周日 20:00 准点把速览递给你 —— 这是纯 H5 版做不到的。

> **启动方式**：双击本目录里的 **`启动.cmd`**。
> 或者命令行：`npx electron .`（注意见下方"环境变量陷阱"）

---

## 与纯 H5 版的区别

| | H5 版（`..\index.html`） | 托盘版（本目录） |
|:--|:--|:--|
| 定时投递 | **页面必须开着**，关掉就不推 | ✅ **关掉也推**（独立进程 + 定时器） |
| 补充投递 | 下次打开时补投 | ✅ 同样补投，并提示还有几期积压 |
| 开机自启 | 做不到 | ✅ 托盘菜单里可开关 |
| 系统通知 | 走浏览器 Notification | ✅ 原生通知 |
| 未读红点 | 页面内 📬 图标 | ✅ **直接叠在托盘图标上** |
| 休眠唤醒 | 靠 `visibilitychange` | ✅ 监听 `powerMonitor.resume` |
| 单实例 | — | ✅ 重复启动会唤出气泡，不会开出两个托盘 |

**两个版本共用同一份期数清单**（见下），所以不会出现"加了一期只更新了一边"。

## 界面配色：白底（浅色）

气泡弹窗和桌宠的三个小按钮都是**白底深字**，配浅色桌面/任务栏。

| 元素 | 配色 |
|:--|:--|
| 气泡弹窗 | 白底 `#ffffff`、浅灰描边、深色正文；高亮用深青 `#0d9488` |
| 勘误区块 | 暖琥珀色调（在白底上可读，不用原来的亮黄） |
| 桌宠三个按钮 | 白底、深灰图标、浅灰描边、轻投影 |
| 未读红点 | `#e11d48`，外圈白色描边 |

> 原来是深色主题。改成白底是因为**你的任务栏是浅色的**（注册表
> `SystemUsesLightTheme = 0x1`），深色弹窗配浅色桌面很跳。
> 如果你后来换成深色任务栏，想要回深色主题，跟我说一句就行。

### 顺手修掉的一个"隐形"问题

透明底头像里**残留了一层 alpha 1–40 的底板鬼影**（占 8.68% 像素）。
在深色背景上完全看不出，但在**白色桌面上会显成一个极淡的灰方块**。

我之前的检测阈值是 `alpha > 40`，正好把它漏掉了。已清掉（阈值 48）：
清理后 solid 19.41% / semi 0.14% / 完全透明 80.45%。鲸鱼真正的抗锯齿边缘只占
0.14%，所以清掉这些不影响边缘质量。H5 版用的同一份文件也同步更新了。

## 托盘图标为什么要单独一套图

托盘图标画在**任务栏**上，必须与任务栏明暗形成对比 —— 而气泡头像那张
（透明底深色鲸鱼）在深色任务栏上几乎看不见。实测数据（16×16）：

| 图标 | 可见覆盖率 | 可见部分亮度 | 深色任务栏 | 浅色任务栏 |
|:--|:--|:--|:--|:--|
| `whale-ink.png`（原方案，也是头像） | 21% | **94/255** | ❌ **几乎看不见** | ✅ 可以 |
| `whale-official.png` | 86% | 202/255 | ✅ 清楚 | ✅ 清楚 |
| `tray-dark-bar.png`（白鲸） | 35% | **255/255** | ✅ **最醒目** | ❌ 白对白 |
| `tray-light-bar.png`（深鲸+白描边） | 22% | 111/255 | ✅ 可以 | ✅ **清楚** |

所以托盘图标**与头像解耦**，并按任务栏配色自动选（读注册表
`HKCU\...\Themes\Personalize\SystemUsesLightTheme`）。菜单里可手动强制。

## 期数清单只有一份

本程序**不维护自己的期数列表** —— 它直接读桌宠的 `..\index.html`，把里面的
`var ISSUES = [ ... ];` 抽出来求值（用 `vm` 在空沙箱里跑，拿不到 `require`/`process`）。

所以**加新一期只需要改一处**：

1. 把新速览 HTML 放进 `..\issues\`
2. 在 `..\index.html` 的 `ISSUES` 数组最前面插一条

本程序下次读的时候就会看到。**不需要改本目录任何文件。**

投递时刻的算法也与桌宠**完全一致**（`range` 结束日所在那一周的周日 20:00），
两边不会算出不同的时间。

## ⚠️ 两个实测踩到的坑

### 1. 环境变量陷阱（启动失败首选排查）

如果启动时报这种错：

```
TypeError: Cannot read properties of undefined (reading 'on')
    at Object.<anonymous> (.../main.js:...:ipcMain.on)
```

那不是代码问题，而是环境里有：

```
ELECTRON_RUN_AS_NODE=1
```

**这个变量会让 Electron 退化成纯 Node。** 后果是 `require('electron')` 只返回一个
路径字符串，于是 `ipcMain` / `Tray` / `app` 全是 `undefined`，程序启动即崩。

- **`启动.cmd` 会自动清掉它**，所以正常双击就行
- 命令行启动时请自己处理：
  ```bat
  set ELECTRON_RUN_AS_NODE=
  node_modules\electron\dist\electron.exe .
  ```

（这个坑是实测踩出来的：本机 DSH 会话里该变量为 `1`。）

### 2. `启动.cmd` 必须写成纯 ASCII

第一版我给它写了中文注释和制表符，结果**启动直接失败**，报一堆
`'════════' is not recognized as an internal or external command`。

原因：**批处理文件由 cmd.exe 按 OEM 代码页（中文系统是 GBK）读取**，而文件是 UTF-8
保存的。中文和 `═` 这类字符被拆成非法字节序列后，会把 `rem` 注释行截断成独立命令。

所以现在这个 `.cmd` **只有 ASCII 字符**（已验证非 ASCII 字节数为 0），
中文说明都放在这份 README 里。**如果你要改它，请勿加入中文。**

```bat
cd electron-tray
```

### 如果卡在下载 Electron 二进制

GitHub Releases 在国内经常不可达（本机实测 **`github.com` 超时**）。本目录已带
`.npmrc` 指向国内镜像：

```
electron_mirror=https://npmmirror.com/mirrors/electron/
```

```bat
node node_modules\electron\install.js
```

```bat
set ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/
node node_modules\electron\install.js
```

## 自检与截图（用于排查）

不建窗口，只跑调度与资源逻辑，结果写入 `selftest.txt`：

```bat
set ELECTRON_RUN_AS_NODE=
node_modules\electron\dist\electron.exe . --selftest
```

起一个真实气泡窗口、抓图后退出（用于确认渲染没问题）：

```bat
node_modules\electron\dist\electron.exe . --shot=D:\tmp\bubble.png
```

会同时写出同名 `.json`，里面是渲染进程的 DOM 快照（标题、文件名、正文字数、
`window.pet` 是否存在、控制台报错），排查白屏很有用。

> **为什么自检要写文件**：Electron 在 Windows 上不往父控制台写 stdout（GUI 程序
> 脱离控制台），只 `console.log` 是看不到的。

## 状态存在哪里

配置与投递记录存在 Electron 的用户数据目录，**不在本文件夹**：

```
%APPDATA%\weeklypet-tray\config.json     ← 投递时间、头像、自启
%APPDATA%\weeklypet-tray\state.json      ← 已投递 / 未读 / 已读
```

删掉它们就等于恢复出厂设置（已投递记录清空 → 下次启动会把到点的期数重新投一遍）。

### 真实投递记录（2026-10-11 周日）

```
lastShown : 2026-10-11T12:00:01.737Z   →  北京时间 20:00:01
delivered : ["2026-10-04_10"]
unread    : 1        ← 12 秒内没点，气泡自动收起 → 托盘图标出现红点（符合设计）
```

旁证：投递瞬间第 4 个 Electron 进程起于 `20:00:01` —— 那正是气泡窗口的渲染进程
被创建的时刻。下一期自动投递时间：**2026-10-18（周日）20:00**。

**唯一仍未由我验证的**：系统托盘图标的视觉效果 —— 我无法观察通知区域，
只能程序化确认图标生成成功。这一条需要你自己看一眼。

> **验证"到点自动投递"的正确方法**：不能直接改真实配置——那会消耗掉当期的投递资格。
> 要用 `--user-data-dir=<临时目录>` 起一个隔离实例，在里面设一个几分钟后的时刻，
> 真实实例完全不受影响。我第一次就搞错了：把 `weekday` 设成 6（周六），
> 结果计划时刻落在**昨天**，程序启动即"补投"——那验证的是补投路径而不是前向定时。

## 开发过程中修掉的三个真 bug（都是实测才暴露）

**1. `did-finish-load` 重入导致消息永久挂起**
原先用 `webContents.isLoading()` 判断渲染进程是否就绪：
```js
if (win.webContents.isLoading()) win.webContents.once('did-finish-load', send);
else send();
```
但在 **`did-finish-load` 事件派发期间**，`isLoading()` 仍可能返回 `true`。此时再注册一个
`once('did-finish-load')`，而那个事件**已经不会再触发** —— `send()` 永远不会执行，
表现是**窗口全白、气泡不显示任何内容**。

改成显式的就绪标志（`win.__ready` + `__pending` 队列），两种竞态都安全。

**2. vm 沙箱对象跨 realm 传输**
期数清单是在 `vm` 里求值的，那些对象来自**另一个 realm**。为稳妥起见，
`send()` 前先做一次 `JSON.parse(JSON.stringify(payload))` 转成本 realm 的纯对象。

**3. 配置文件带 UTF-8 BOM 时被静默忽略**
`JSON.parse` 遇到 BOM（`EF BB BF`）会**直接抛错**。而写 BOM 是家常便饭：
**记事本另存为 UTF-8 会写 BOM，PowerShell 5.1 的 `Set-Content -Encoding UTF8` 也写 BOM**。

后果很隐蔽：`loadJSON` 的 `catch` 把异常吞掉并回退到默认值，于是
**你改了 `config.json` 却完全不生效**，程序照旧按周日 20:00 跑，没有任何报错。

这个 bug 是我自己写测试配置时踩出来的——查了文件头才发现是 `239,187,191`。
修法两处：
```js
// 读：剥掉 BOM
if (raw.charCodeAt(0) === 0xFEFF) raw = raw.slice(1);
// 写：显式无 BOM（用 Buffer 而不是 writeFileSync 的 'utf8' 字符串）
fs.writeFileSync(file, Buffer.from(JSON.stringify(obj, null, 2), 'utf8'));
```
并已实测：故意写入带 BOM 的配置（`hour: 19`），程序能正确读到 `19` 而不是回退默认值。
